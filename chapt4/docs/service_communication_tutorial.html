01 / OVERVIEW

先用一分钟看懂这个项目

你的项目模拟“给机器人下发巡逻点”。客户端说要去哪里，服务端根据参数 allow 决定接不接，并把结果答回去。

全篇最重要的一句话

客户端填写 Request，服务端读取请求并填写 Response。

patrol_client target_name = "room_A" 提出问题
Request
Response
patrol_server allow ? accepted : rejected 处理并回答
输入 目标点名称

string target_name，例如 room_A。

判断 是否允许任务

服务端参数 allow 默认为 true。

输出 接受状态 + 消息

bool accepted 与 string message。

一次真实调用会发生什么？

  1. 服务端启动

    节点注册名为 patrol_task 的服务，并等待请求。

  2. 客户端寻找服务

    每隔 1 秒检查一次。如果没发现，就输出 waiting 日志。

  3. 客户端发送请求

    从参数 target_name 取得 room_A，写进请求对象。

  4. 服务端做决定

    读取 robot_name 和 allow；默认会接受任务。

  5. 客户端打印答案

    得到 accepted: True 和带机器人名称的说明。

02 / BASICS

ROS 2 基础地图

先把经常混淆的名词摆到正确层级。ROS 2 的核心不是“运行一堆脚本”，而是让多个节点组成一张可发现、可通信的计算图。

Workspace工作空间

容纳多个包的开发目录。你的工作空间是 chapt4_ws。

Package功能包

ROS 2 的构建和分发单元。本项目有 2 个包。

Node节点

一个运行中的功能实体，例如服务端节点。

Interface接口

通信双方共同遵守的数据结构：.msg、.srv、.action。

Graph计算图

当前节点、话题、服务和动作组成的动态关系图。

DDS底层通信

ROS 2 通常借助 DDS 做节点发现和数据传输，你写 rclpy 时无需直接操作它。

Topic、Service、Action 怎么选？

方式通信感觉适合不适合例子
Topic持续发布 / 订阅连续数据流必须得到一次明确答复相机图像、雷达、速度指令
Service一次请求 / 一次响应短时、快速完成的查询或操作耗时很久、要进度、要取消查询状态、切换模式、下发简单任务
Action目标 / 反馈 / 结果长任务、有进度、可取消高频连续数据导航到目标点、机械臂抓取
巡逻在真实项目里可能更适合 Action

本例的服务只回答“接不接受”，非常快，因此 Service 合理。如果要等机器人真的走到房间、持续反馈百分比并允许取消，就应改用 Action。

包、节点、可执行程序不是同一个东西

概念本项目实例如何查看

可执行程序名patrol_serverros2 pkg executables patrol_service_demo

03 / SERVICE

Service 的心智模型

把服务想成带固定表格的客服窗口：双方先约定表格格式，客户端提交请求表，服务端填写答复表。

概念伪代码
# 客户端
request = PatrolTask.Request()
request.target_name = "room_A"
future = client.call_async(request)

# 服务端回调
def callback(request, response):
    response.accepted = True
    response.message = "任务已接受"
    return response

为什么叫异步调用？

call_async() 不会当场给出结果，而是先返回一个 Future——可以理解成“将来会装入结果的盒子”。本项目随后用 spin_until_future_complete() 驱动事件循环，直到这个盒子完成。

异步 API，不等于程序一定并行

这里仍然主动等到 Future 完成才继续，所以从业务流程看，它像同步等待；优势是等待过程交给 ROS 2 执行器处理。

服务能否“记住”客户端？

普通 Service 是离散的一问一答。服务端可以在节点对象里保存自己的状态，但每次请求本身并不天然形成长会话。若需要任务生命周期、进度和取消，应考虑 Action。

06 / SERVER

服务端逐行读

服务端做四件事：创建节点、声明参数、注册服务、在回调里填写响应。

patrol_server.py · 核心代码（与项目一致）
import rclpy
from chapt4_interfaces.srv import PatrolTask
from rcl_interfaces.msg import SetParametersResult
from rclpy.node import Node

class PatrolServer(Node):
    def __init__(self):
        super().__init__('patrol_server')
        self.declare_parameter('robot_name', 'robot-01')
        self.declare_parameter('allow', True)
        self.add_on_set_parameters_callback(self.on_parameter_update)
        self.service = self.create_service(
            PatrolTask, 'patrol_task', self.handle_patrol_task)

    def on_parameter_update(self, pars):
        for par in pars:
            if par.name == 'robot_name' and par.value == '':
                return SetParametersResult(
                    successful=False, reason='robot_name cannot be empty')
        return SetParametersResult(successful=True)

    def handle_patrol_task(self, request, response):
        robot_name = self.get_parameter('robot_name').value
        allow_task = self.get_parameter('allow').value
        if allow_task:
            response.accepted = True
            response.message = robot_name + ' accepted target: ' + request.target_name
        else:
            response.accepted = False
            response.message = robot_name + ' rejected target: ' + request.target_name
        return response
01
class PatrolServer(Node)

继承 Node，获得日志、参数、服务、定时器等 ROS 2 能力。类名是 Python 概念，节点名由下一行决定。

02
super().__init__('patrol_server')

初始化 ROS 节点。运行后 ros2 node list 会看到 /patrol_server。

03
declare_parameter(...)

参数要先声明才能按常规方式读写。这里给出两个默认值，ROS 2 会推断 STRING 与 BOOL 类型。

04
add_on_set_parameters_callback(...)

参数真正修改前先审查。若 robot_name 为空字符串，就返回失败并说明原因。

05
create_service(类型, 名称, 回调)

注册 /patrol_task。类型必须和客户端相同；名称也必须解析到同一个服务。

06
handle_patrol_task(request, response)

每来一个请求，执行一次。读取 request.target_name，填写响应的两个字段，最后返回 response。

main() 为什么必须 spin？

patrol_server.py · 生命周期
def main(args=None):
    rclpy.init(args=args)       # 初始化 ROS 2 客户端库
    node = PatrolServer()       # 创建节点
    try:
        rclpy.spin(node)        # 持续处理请求和事件
    finally:
        rclpy.shutdown()        # Ctrl+C 后关闭

spin() 相当于节点的“接线员”：不断等待并分发服务请求、订阅消息和参数事件。没有它，脚本创建完节点就退出，回调永远没机会执行。

当前源码在 Humble 下停止时可能打印 shutdown 回溯

实测服务调用本身正常，但 SIGINT/Ctrl+C 的默认处理可能已经关闭 rclpy，finally 又调用一次 rclpy.shutdown()，于是出现 rcl_shutdown already called。可改用 rclpy.try_shutdown()，或先判断上下文是否仍为 ok()；这属于退出清理问题，不是服务请求失败。

07 / CLIENT

客户端逐行读

客户端不长期 spin，而是等服务、发送一次、等结果、打印后退出。

patrol_client.py · 核心代码（与项目一致）
class PatrolClient(Node):
    def __init__(self):
        super().__init__('patrol_client')
        self.declare_parameter('target_name', 'room_A')
        self.client = self.create_client(PatrolTask, 'patrol_task')

    def send_reauest(self):
        while not self.client.wait_for_service(1.0):
            self.get_logger().info('waiting for patrol_task service...')

        request = PatrolTask.Request()
        request.target_name = self.get_parameter('target_name').value
        fu = self.client.call_async(request)
        rclpy.spin_until_future_complete(self, fu)
        response = fu.result()
        self.get_logger().info('accepted: ' + str(response.accepted))
        self.get_logger().info('message: ' + response.message)
01
create_client(PatrolTask, 'patrol_task')

创建代理。它不会创建服务，只是准备和指定名称、指定类型的服务通信。

02
wait_for_service(1.0)

最多等 1 秒返回一次布尔值。外层 while 让它持续等待，同时周期性打印提示。

03
PatrolTask.Request()

创建由 .srv 生成的请求对象。字段名必须严格是 target_name。

04
call_async(request)

发出请求并立即得到 Future，不是最终 Response。

05
spin_until_future_complete(self, fu)

让当前节点处理 ROS 事件，直到响应到达。之后 fu.result() 才能取到答案。

源码里 send_reauest 拼错了，但目前仍能运行

它只是自定义方法名，而且 main() 也用同样的拼法调用，所以 Python 找得到。建议以后重命名为 send_request，可读性更好；这不是 ROS 2 规定的方法名。

为什么客户端执行完会退出？

send_reauest() 等到响应后返回；finally 中销毁节点并 shutdown。它不是持续服务，不需要一直在线。

09 / PARAMETERS

参数：运行时调节节点行为

参数属于节点，类似节点的可配置设置。本项目用 robot_name 控制回复中的名称，用 allow 控制接受或拒绝。

参数节点默认值 / 类型作用
robot_name/patrol_server"robot-01" / string写进响应消息；不允许空字符串
allow/patrol_servertrue / bool决定接受还是拒绝任务
target_name/patrol_client"room_A" / string写入请求；客户端结束后该参数随节点消失

用 CLI 查看和修改

服务端保持运行时执行
ros2 param list /patrol_server
ros2 param get /patrol_server robot_name
ros2 param get /patrol_server allow

ros2 param set /patrol_server robot_name robot_02
ros2 param set /patrol_server allow false

此时再调用服务，应该得到 accepted: false，消息含 robot_02 rejected target...。

验证参数回调确实在保护数据

空字符串会被拒绝
ros2 param set /patrol_server robot_name ""
# 预期：Set parameter failed: robot_name cannot be empty

代码方式远程改参数

remote_param_setter.py 没有直接访问另一个进程的变量，而是调用每个节点自动提供的参数服务：

remote_param_setter.py · Humble 兼容方式
from rcl_interfaces.srv import SetParameters

self.client = self.create_client(
    SetParameters, '/patrol_server/set_parameters')

request = SetParameters.Request()
request.parameters = [
    Parameter('robot_name', Parameter.Type.STRING,
              'robot_02').to_parameter_msg(),
    Parameter('allow', Parameter.Type.BOOL,
              False).to_parameter_msg(),
]
future = self.client.call_async(request)
rclpy.spin_until_future_complete(self, future)
运行远程改参节点
ros2 run patrol_service_demo remote_param_setter

监听所有节点的参数事件

parameter_event_watcher.py 订阅系统话题 /parameter_events，把新建、改变、删除的参数打印出来：

终端 A 监听；终端 B 改参

# 终端 B

参数服务与业务服务是两套服务

/patrol_task 是你创建的业务服务；/patrol_server/set_parameters 是节点参数机制提供的服务。它们的类型、用途和请求字段都不同。

        request = PatrolTask.Request()
        request.target_name = target
        future = self.cli.call_async(request)
        rclpy.spin_until_future_complete(self, future)
        return future.result()

def main():
    rclpy.init()
    node = Client()
    response = node.send_request('room_C')
    node.get_logger().info(response.message)
    node.destroy_node()
    rclpy.shutdown()

12 / DEBUG

故障排查与当前代码体检

按现象找“最小可疑范围”，比反复删除 build 目录更有效。下面同时记录了对当前源码的实际观察。

Package 'patrol_service_demo' not found

先执行 source /opt/ros/humble/setup.bash 和工作空间的 source install/setup.bash。若仍不存在，确认在 chapt4_ws 根目录成功执行过 colcon build。

No executable found

运行 ros2 pkg executables patrol_service_demo。检查 setup.py 中入口名称、模块路径和 :main，改过 setup.py 后要重新构建再 source。

客户端一直输出 waiting

先检查服务端是否仍在运行，再执行 ros2 service list -t | grep patrol。两边服务名必须解析一致，类型都必须是 chapt4_interfaces/srv/PatrolTask。不同机器还要检查 ROS_DOMAIN_ID 和网络发现。

ModuleNotFoundError: chapt4_interfaces

通常是接口包没构建或当前终端没加载 overlay。执行接口构建、source，然后用 ros2 interface show... 验证。Python 业务包的 package.xml 已正确声明 <depend>chapt4_interfaces</depend>。

CLI 服务调用提示字段或 YAML 错误

先用 ros2 interface show 查看精确字段。请求必须是 YAML 映射，例如 "{target_name: room_B}"，字段名不能写成 target。

修改 .srv 后行为没有变化

接口是生成代码，必须重新构建依赖它的包并重新 source。最直接的方式是回到工作空间运行 colcon build --symlink-install，然后在所有终端重新 source，并重启节点。
