先建立正确的心智模型

Launch 像“舞台导演”。节点是演员，参数是演员拿到的剧本设定，命名空间是不同舞台的房间号，条件则决定某个演员今天是否出场。

概念准确含义本项目实例
工作区 workspace包含 src、build、install、log 的工程目录chapt4_service
功能包 packageROS 2 分发与发现代码的最小单位patrol_service__demo
节点 node参与 ROS 图的独立进程/组件servzer_node、patrol_client
服务 service一问一答的同步语义通信partrol_service
接口 interface通信数据结构的契约service_interfaces/srv/Patrol
节点参数 parameter属于某个节点、运行时可查询或修改的配置robot_name、allow_task
Launch 参数启动文件自身接收的输入，本质先是字符串替换robot_name:=xiaoye
Launch action启动系统要执行的动作Node、GroupAction
Substitution启动执行时才求值的占位符LaunchConfiguration
最关键的区别：DeclareLaunchArgument 声明的是 launch 的输入；只有把 LaunchConfiguration(...) 放进 Node(parameters=[...])，这个输入才真正成为节点参数。

话题像广播，服务像问答，动作像能汇报进度并取消的长任务。Launch 不替代它们；Launch 只负责把使用这些通信方式的节点组织并启动起来。

第一课：用一个 launch 启动多个节点

手动方式需要两个终端分别执行 ros2 run。Launch 把这两条启动意图写成一份可版本管理的 Python 描述。

launch/01_multiple_nodes.launch.py
"""第一课：一个 launch 同时启动服务端和客户端。"""

from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    return LaunchDescription([
        Node(
            package='patrol_service__demo',
            executable='patrol_server',
            name='servzer_node',
            output='screen',
        ),
        Node(
            package='patrol_service__demo',
            executable='partom_client',
            name='patrol_client',
            output='screen',
        ),
    ])

逐块理解

代码作用常见误解
generate_launch_description()ROS 2 launch 查找并调用的固定入口名字不能随便改
LaunchDescription([...])收集要执行的 actions它不是节点，本身不参与 ROS 通信
Node(package=...)描述一个 ROS 节点进程package 是包名，不是 Python 模块路径
executable=...对应 setup.py 的 console_scripts 左侧名称不是 Python 文件名
name=...覆盖节点代码里的默认节点名它不改变 executable
output='screen'把日志显示在启动终端调试初期建议保留
终端 1 · 运行
source /opt/ros/$ROS_DISTRO/setup.bash
source install/setup.bash
ros2 launch patrol_service__demo 01_multiple_nodes.launch.py
终端 2 · 观察（只读命令）
source /opt/ros/$ROS_DISTRO/setup.bash
source install/setup.bash
ros2 node list
ros2 service list -t
ros2 node info /servzer_node
本章成功标准：终端 1 出现 accept:True；终端 2 至少能看到 /servzer_node。客户端发完一次请求就正常退出，因此你稍晚执行 ros2 node list 时可能看不到客户端——这是预期行为。
为什么客户端可以和服务端“同时启动”？会不会抢跑？
两个进程的启动先后不能被简单假定。但客户端的 wait_for_service(1.0) 会反复等待服务出现，所以即使客户端先启动，也不会立即调用失败。这是节点代码自身的健壮性，不能只依赖 launch 文件中的书写顺序。

第二课：使用 launch 传递参数

目标是让同一个启动文件适应不同机器人和任务地点，而不是每次修改 Python 源码。

命令行robot_name:=xiaoye
→
LaunchArgument声明输入
→
LaunchConfiguration运行时取值
→
Node parameters节点参数
launch/02_launch_arguments.launch.py
"""第二课：用 ros2 launch 的命令行参数配置节点。"""

from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node


def generate_launch_description():
    robot_name = LaunchConfiguration('robot_name')
    allow_task = LaunchConfiguration('allow_task')
    target_name = LaunchConfiguration('target_name')

    return LaunchDescription([
        DeclareLaunchArgument(
            'robot_name', default_value='robot-01', description='服务机器人名称'),
        DeclareLaunchArgument(
            'allow_task', default_value='true', description='是否接受巡逻任务'),
        DeclareLaunchArgument(
            'target_name', default_value='room-A', description='客户端请求的目标地点'),
        Node(
            package='patrol_service__demo',
            executable='patrol_server',
            name='servzer_node',
            output='screen',
            parameters=[{
                'robot_name': robot_name,
                'allow_task': allow_task,
            }],
        ),
        Node(
            package='patrol_service__demo',
            executable='partom_client',
            name='patrol_client',
            output='screen',
            parameters=[{'target_name': target_name}],
        ),
    ])

先看参数清单，再运行

终端 · 查询和传参
# 查看：不会启动节点
ros2 launch patrol_service__demo 02_launch_arguments.launch.py --show-args

# 改变系统：启动节点，并覆盖三个默认值
ros2 launch patrol_service__demo 02_launch_arguments.launch.py \
  robot_name:=xiaoye \
  allow_task:=false \
  target_name:=lab-A

预期响应是 accept:False 和“不允许接受任务”。因为 launch 把 false 交给服务端的 allow_task 参数。

不传参时传参时流向
robot-01xiaoye服务端 robot_name
truefalse服务端 allow_task
room-Alab-A客户端 target_name
延迟求值：LaunchConfiguration('robot_name') 不是立刻读取字符串。它是一个 substitution，占位到 launch 真正执行时才取得当前上下文中的值。
布尔参数写法：命令行使用 allow_task:=true 或 false，不要加 Python 引号。ROS 参数解析会根据节点已声明的类型将它交给布尔参数。

运行时验证参数

客户端很快退出，因此另开终端查询仍在运行的服务端：

终端 2 · 参数检查
ros2 param list /servzer_node
ros2 param get /servzer_node robot_name
ros2 param get /servzer_node allow_task

# 下面会改变正在运行的系统
ros2 param set /servzer_node robot_name patrol-007
本章成功标准：--show-args 能看到三个参数及默认值；传入 allow_task:=false 后客户端收到拒绝响应。

第三课：Launch 进阶编排

当系统变大，关键不再是“多写几个 Node”，而是复用、隔离、配置和按需组合。

launch/03_advanced.launch.py
"""第三课：包含其他 launch、命名空间、YAML 参数和条件启动。"""

from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument, GroupAction, IncludeLaunchDescription
from launch.conditions import IfCondition
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.substitutions import LaunchConfiguration, PathJoinSubstitution
from launch_ros.actions import Node, PushRosNamespace
from launch_ros.substitutions import FindPackageShare


def generate_launch_description():
    package_share = FindPackageShare('patrol_service__demo')
    namespace = LaunchConfiguration('namespace')
    start_remote_param = LaunchConfiguration('start_remote_param')
    params_file = LaunchConfiguration('params_file')

    base_launch = PathJoinSubstitution([
        package_share, 'launch', '02_launch_arguments.launch.py'])
    default_params = PathJoinSubstitution([
        package_share, 'config', 'patrol_params.yaml'])

    return LaunchDescription([
        DeclareLaunchArgument(
            'namespace', default_value='floor_1',
            description='给本组节点加的命名空间'),
        DeclareLaunchArgument(
            'start_remote_param', default_value='true',
            description='是否启动远程参数节点'),
        DeclareLaunchArgument(
            'params_file', default_value=default_params,
            description='ROS 参数 YAML 文件'),
        GroupAction([
            PushRosNamespace(namespace),
            IncludeLaunchDescription(
                PythonLaunchDescriptionSource(base_launch),
                launch_arguments={
                    'robot_name': 'launch-robot',
                    'allow_task': 'true',
                    'target_name': 'loading-area',
                }.items(),
            ),
            Node(
                package='patrol_service__demo',
                executable='remote_param',
                name='remote_param',
                output='screen',
                parameters=[params_file],
                condition=IfCondition(start_remote_param),
            ),
        ]),
    ])

进阶机制 1：定位安装后的包

FindPackageShare('patrol_service__demo') 找到包安装后的 share 目录。不要硬编码 /home/某用户/...，否则换机器就失效。

PathJoinSubstitution 把包路径、launch、文件名安全拼接，并保留 launch 的延迟求值能力。

进阶机制 2：Include 复用启动文件

IncludeLaunchDescription 把第二课整体当成一个子模块，同时通过 launch_arguments={...}.items() 给子 launch 传值。大型机器人通常会把相机、导航、机械臂分别做成 launch，再由顶层 launch 组合。

进阶机制 3：命名空间隔离

/floor_1/servzer_node
/patrol_client
/remote_param
互不冲突
/floor_2/servzer_node
/patrol_client
/remote_param

GroupAction 创建一个作用域，PushRosNamespace(namespace) 让组内后续 action 都使用相同命名空间。这样可以运行两套相同节点而不重名。

为什么 remote_param.py 使用相对名？它连接的是 servzer_node/set_parameters，没有开头的 /。因此进入 /floor_1 后会自动解析为 /floor_1/servzer_node/set_parameters。若写成绝对名 /servzer_node/set_parameters，命名空间隔离就会失效。

进阶机制 4：YAML 参数文件

config/patrol_params.yaml
remote_param:
  ros__parameters:
    # 当前 remote_param.py 写死了要修改的两个远程参数。
    # 此文件演示 launch 加载 YAML 的标准结构。
    use_sim_time: false

YAML 最外层通常是节点名，下一层必须是 ros__parameters。当前 YAML 只给 remote_param 设置其自身的 use_sim_time；它不会自动修改服务端。服务端的远程修改逻辑仍来自 remote_param.py。

别混淆两件事：parameters=[params_file] 是“启动时给这个 Node 加载参数”；远程参数节点通过 SetParameters 服务去修改另一个正在运行的节点，这是另一条通信路径。

进阶机制 5：条件启动

condition=IfCondition(start_remote_param) 表示只有值为真时才创建远程参数进程。传入 false 后，服务端和客户端仍启动，但远程参数节点不会出现。

三组实验
# 实验 A：默认进阶启动
ros2 launch patrol_service__demo 03_advanced.launch.py

# 实验 B：换命名空间，并禁用远程参数节点
ros2 launch patrol_service__demo 03_advanced.launch.py \
  namespace:=floor_2 start_remote_param:=false

# 实验 C：查看进阶 launch 暴露的全部参数
ros2 launch patrol_service__demo 03_advanced.launch.py --show-args
本章成功标准：默认启动时日志节点名带 floor_1. 前缀，并出现两次“参数修改成功”；传 start_remote_param:=false 后不再启动 remote_param。
更大型项目还会使用哪些 Launch 能力？
TimerAction 延时执行、RegisterEventHandler 监听进程退出、OnProcessExit 做退出后的动作、SetEnvironmentVariable 配置环境、ExecuteProcess 启动非 ROS 程序、remappings 改通信名称。先掌握本课四项，再按真实需求引入这些工具。

setup.py 中最容易漏掉的安装规则

setup.py · 关键片段
from glob import glob

data_files=[
    ('share/ament_index/resource_index/packages',
        ['resource/' + package_name]),
    ('share/' + package_name, ['package.xml']),
    ('share/' + package_name + '/launch', glob('launch/*.launch.py')),
    ('share/' + package_name + '/config', glob('config/*.yaml')),
    ('share/' + package_name + '/docs', glob('docs/*.html')),
]

源码目录中存在 launch 文件还不够。ros2 launch 从安装空间的 package share 中查找它；没有 data_files 规则时，构建后仍会提示找不到 launch 文件。

package.xml 的运行依赖

package.xml · 关键片段
<depend>rclpy</depend>
<depend>service_interfaces</depend>
<depend>rcl_interfaces</depend>
<exec_depend>launch</exec_depend>
<exec_depend>launch_ros</exec_depend>
为什么 Python 节点包没有 CMakeLists.txt？
patrol_service__demo 是 ament_python 包，构建和安装规则由 setup.py 管理。service_interfaces 需要 rosidl 生成接口，所以它是独立的 ament_cmake 包并拥有 CMakeLists.txt。把接口生成硬塞进纯 ament_python 包容易形成不可构建的结构。
